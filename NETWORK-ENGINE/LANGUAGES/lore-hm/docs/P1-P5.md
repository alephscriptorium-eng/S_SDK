## Respuestas formales

### P1 · ¿Qué problema?

**verificada** (intención plan) — Separar **autoridad H** (anfitrión: concede /
revoca leases, observa cadena) de **operación M** (operador: controla Future
Machine solo mediante actividades legales), sobre un simulacro o provider real,
sin colapsar roles en tipos de ser ni duplicar un segundo JSON plano sin
semántica.

**hipótesis** — El wording exacto del checklist P1 en el árbol OASIS LANGUAGES
coincide con esta formulación; no se releyó el fichero OASIS en este WP.

### P2 · ¿Quién habla?

**verificada** — El sujeto es `Peer`. H y M son **roles/capacidades** del Peer,
no primitivas ni tipos ontológicos distintos. Una Unit actúa bajo Lease
concedida a un Peer en rol.

### P3 · ¿Qué no es?

**verificada** — LORE-HM **no** es:

- barrio (`document-machine-sdk` / lore-voz);
- holón 08 ni mundo `L_SDK`;
- segundo lenguaje JSON plano sin tipestate;
- runtime OASIS / Network-Engine contenedor;
- package `@logos/lore-hm` (aún no; ver P5).

### P4 · ¿Cómo se valida?

**verificada** (esta entrega) — Reference checker local
(`scripts/verificar-inception-l02.mjs`) + gramática TypeScript declarativa
(uniones discriminadas, phantom states, exhaustividad). El JSON/wire describe
una corrida; la lengua decide legalidad.

**verificada** — Al menos una regla **imposible** de expresar/validar con config
plana: tipestate de Unit (`declared → leased → inflated → ready → running`),
demostrada en `demos/tipestate-vs-flat/` (intento flat fallido al lado).

### P5 · ¿Cuándo promover?

**verificada** — Solo cuando se cumplan **todos** los gates de
[`PUERTA-PROMOCION.md`](PUERTA-PROMOCION.md):

1. Inception Review aprobada
2. WP-E01 de E ratificada
3. Una línea sintética cruzando E11
4. Dos consumidores compilando

Entonces — y solo entonces — se extrae `@logos/lore-hm`. El origen definitivo
lo decide el custodio con esa evidencia. Esta incubación **no** extrae package.
