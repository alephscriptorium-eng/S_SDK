## Respuestas formales

### P1 · ¿Qué problema?

**verificada** (intención plan) — Separar **autoridad H** (anfitrión: concede /
revoca leases, observa cadena) de **operación M** (operador: controla Future
Machine solo mediante actividades legales), sobre un simulacro o provider real,
sin colapsar roles en tipos de ser ni duplicar un segundo JSON plano sin
semántica.

**hipótesis** — El wording exacto del checklist P1 en el árbol OASIS LANGUAGES
coincide con esta formulación; no se releyó el fichero OASIS en este WP.

### P2 · ¿Quién habla?

**verificada** — El sujeto es `Peer`. H y M son **roles/capacidades** del Peer,
no primitivas ni tipos ontológicos distintos. Una Unit actúa bajo Lease
concedida a un Peer en rol.

### P3 · ¿Qué no es?

**verificada** — LORE-HM **no** es:

- barrio (`document-machine-sdk` / lore-voz);
- holón 08 ni mundo `L_SDK`;
- segundo lenguaje JSON plano sin tipestate;
- runtime OASIS / Network-Engine contenedor;
- package `@logos/lore-hm` (aún no; ver P5).

### P4 · ¿Cómo se valida?

**verificada** (esta entrega) — Reference checker local
(`scripts/verificar-inception-l02.mjs`) + gramática TypeScript declarativa
(uniones discriminadas, phantom states, exhaustividad). El JSON/wire describe
una corrida; la lengua decide legalidad.

**REFUTADA por medición (WP-ZV-S ⓪)** — la respuesta anterior decía «al menos
una regla *imposible* de expresar/validar con config plana: tipestate de Unit».
**Es falsa.** Cuando se escribieron los JSON Schema 2020-12 que la demo nunca
tuvo y se ejecutaron, las tres formas de `demos/tipestate-vs-flat/flat-schema/`
rechazan `declared→ready` y aceptan `declared→leased`. Confirmado con
`ajv@8.20.0`, 0 desviaciones.

**Lo que sí queda verificado**, y con la anchura que la medición sostiene:

- La regla **sí** se expresa con configuración plana. No hay regla imposible.
- La garantía del esquema plano **depende del estilo con que se escriba**, y el
  formato no obliga a ninguno: la forma A (restricción por excepción,
  `if`/`then` por caso) queda *silenciosamente permisiva* al añadir una fase al
  `enum` sin su rama; las formas B y C (enumeración de lo permitido) quedan
  fail-closed ante el mismo olvido — igual que `tsc`. Las tres se miden en cada
  corrida de `reject-flat-illegal.mjs`.
- Lo que el tipestate aporta no es expresividad ni —contra lo que este documento
  llegó a decir en una versión intermedia— exhaustividad *per se*: es que la
  forma cerrada es la **única** que TypeScript deja escribir (una unión es
  cerrada; `never` en `describePhase` lo comprueba), mientras que en JSON Schema
  las dos formas son igual de idiomáticas y **nada avisa de cuál se escribió**.

Detalle, salidas literales y casos rojos: `demos/tipestate-vs-flat/README.md`
y `../REPORTE-ZV-S.md` §⓪ y §B4.

### P5 · ¿Cuándo promover?

**verificada** — Solo cuando se cumplan **todos** los gates de
[`PUERTA-PROMOCION.md`](PUERTA-PROMOCION.md):

1. Inception Review aprobada
2. WP-E01 de E ratificada
3. Una línea sintética cruzando E11

Entonces — y solo entonces — se extrae `@logos/lore-hm`. El origen definitivo
lo decide el custodio con esa evidencia. Esta incubación **no** extrae package.
